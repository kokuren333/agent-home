# 自由意志大政奉還

> この文書は初期仕様の保存版です。現行仕様はREADME.mdとdocs/IMPLEMENTATION_NOTES.mdの「現行実装追補」を優先します。現行の大政奉還メニューは「基本方針」「行動規範」「状態監査」「監査履歴」です。旧メニュー・旧質問数・旧ZIP形式の記述は現行実装の指示ではありません。

## ChatGPT Sites 実装指示書

## 0. アプリの目的

「自由意志大政奉還」という名称の、完全静的なWebアプリを実装する。

このアプリは自己啓発アプリではない。

目的は、

- ユーザー自身について大量の情報を収集する
- 自分史と心理測定の両方から、その人物の特性・希望・制約を構造化する
- その情報をChatGPTへ渡せる形式で書き出す
- ChatGPTが生成した「人生の基本方針」「状態監査モデル」「変更条件」等を再インポートする
- 以後はその方針を参照し、状態に応じて行動方向を判定する
- 一時的な感情や衝動による方針変更には摩擦を設ける

こと。

AI推論はWebアプリ内部では行わない。

Webアプリは、

**入力・保存・構造化・表示・状態監査・ZIP入出力**

のみを担当する。

ChatGPTとのやり取りは、ZIPファイルを介してユーザーが手動で行う。

# 1. 基本思想

アプリ内部では、ユーザーの状態や人生を励ましたり肯定したりしない。

以下のような語彙を避ける。

- 本当の自分
- 夢を叶える
- 自分らしく
- 成長しよう
- あなたならできる
- 理想の人生
- 魂
- 覚醒
- 幸福になる

文章表現はできるだけ無機質・事務的・分析的にする。

例：

悪い例：

「あなたの夢に向かって一歩踏み出しましょう」

良い例：

「判定：現行方針を継続」

「推奨処理：現行目標に関連する作業へ復帰」

「変更条件には該当しません」

# 2. アプリ全体構造

トップレベルのメニューは2つだけにする。

## A. 自由意志

大政奉還前の情報を入力・管理する領域。

機能：

- 簡易入力
- 詳細入力
- 入力内容確認
- 自由意志を読み込む
- 自由意志を書き出す

## B. 大政奉還

ChatGPTによる分析結果をインポートした後に使用する領域。

機能：

- 基本方針
- 状態監査
- 異議申し立て
- 大政奉還を読み込む
- 大政奉還を書き出す

トップレベル機能はこれ以上増やさない。

# 3. デザイン

## 全体方針

極めて無機質にする。

自己啓発サービス、ウェルネスアプリ、瞑想アプリのようなデザインにしない。

方向性：

- 公的機関
- 技術仕様書
- 管理コンソール
- 研究用ツール
- 行政システム

の中間。

## 配色

原則として：

- 白〜薄いグレー背景
- 黒〜濃いグレー文字
- 強調色は1色のみ
- グラデーション禁止
- 過剰な装飾禁止

ダークモード対応は可。

## UI

- 角丸は控えめ
- 絵文字を主要UIに使用しない
- アイコン使用は最低限
- アニメーションは最小限
- ゲーミフィケーション禁止
- XP、レベル、連続日数、称号などは実装しない

完全静的アプリとする。

1. IndexedDB

# 5. 自由意志メニュー

## 5.1 簡易入力

目安所要時間：

**約10分**

別形式の診断を作らない。

### 構成

#### 基本情報

- 年齢

- 主な専門領域
- 現在利用可能な時間

- 避けたい状態
- 維持したい生活条件
- 失いたくないもの

40〜60問程度。

5件法。

1. 全く当てはまらない
2. あまり当てはまらない
3. どちらともいえない
4. やや当てはまる
5. 非常に当てはまる

# 8. 心理測定

詳細入力では、

**120〜180問程度**

を目安とする。

ただしユーザーには「心理学用語」をほぼ表示しない。

Big Fiveを中核にする。

必要なら、

- 自律性
- リスク許容
- 達成志向
- 新奇性への反応
- 反復作業への耐性
- 評価への感受性
- 計画傾向
- 衝動的変更傾向
- 対人負荷
- 不確実性への耐性

なども測定する。

ただし、独自尺度を心理学的に妥当性が証明されたテストであるかのように表現しない。

明示的に、

`本アプリ独自の補助評価`

とする。

---

# 9. 質問設計

同じ概念を、

- 正方向
- 逆方向
- 文脈を変えた質問

で複数回測る。

露骨な重複は避ける。

例：

「一度決めたことは最後まで続けることが多い」

と

「途中で別のことに興味が移りやすい」

を別位置に置く。

回答の一貫性も算出する。

ただし「嘘をついている」などとは表示しない。

例：

`回答一貫性：中`

# 14. README\_FOR\_CHATGPT.md

ZIP内に必ず含める。

ChatGPTへ次の役割を指示する。

## 目的

入力された人物情報を、

- 自分史
- 心理測定
- 希望
- 制約
- 現在の資源

の複数ソースから統合する。

単一の心理尺度だけで判断しない。

単純な性格診断結果を返さない。

最終目的は、

**本人が長期的に進むための基本方針と、状態監査モデルを生成すること。**

# 15. ChatGPT分析時の重要ルール

READMEへ以下を含める。

### 推測と事実を分離する

入力された事実とAIの推論を明確に分ける。

### 過剰な人格断定をしない

例：

NG：

「あなたは継続力のない人間である」

OK：

「提供された情報では、継続性は環境依存性が高い可能性がある」

### 自分史と心理測定が矛盾した場合

一方を自動的に優先しない。

矛盾自体を情報として扱う。

### 医学的診断をしない

心理・精神医学的な診断名を新規に付与しない。

### 最上位方針を一本化する

最終的に、

「複数案から好きなものを選んでください」

では終わらない。

必要な不確実性を明示した上で、

**推奨する基本方針を1つ選択する。**

# 18. 基本方針

大政奉還後の中心画面。

自己啓発的な語彙は使わない。

表示項目：

## 目的

この方針全体が最終的に何を実現しようとしているか。

1〜3文。

## 長期目標

原則1個。

期間目安：

1〜5年。

## 中期目標

2〜5個。

長期目標達成に必要な主要段階。

## 優先順位

最大5項目。

順位を明示。

例：

1. A
2. B
3. C

## 制約

方針実行時に破ってはいけない条件。

例：

- 法的制約
- 経済的上限
- 健康上の制約
- 時間制約
- 地理的制約

## 維持条件

目標達成のためにも維持する必要がある状態。

## 変更条件

この方針自体の再審査を認める条件。

## 終了条件

この大政奉還を完了とみなす条件。

# 21. 状態監査

ユーザーの現在状態を、

Akinator / Twenty Questions型のアルゴリズムで推定する。

固定決定木にはしない。

毎回、現在の候補分布から最も情報量が高い質問を選択する。

---

# 22. 状態候補数

ChatGPTに生成させる状態数：

**8〜12状態**

推奨中央値：

**10状態**

状態を増やす条件：

最終的に提示すべき処理が明確に異なる場合。

統合する条件：

心理学的には異なっていても、

最終的な推奨処理がほぼ同じ場合。

似た状態を無制限に細分化しない。

---

# 23. 状態候補の性質

状態は診断名ではない。

例：

- 方向不明
- 実行開始困難
- 集中逸脱
- 過剰計画
- 情報収集への逃避
- 新規対象への逸脱
- 外部評価への過反応
- 比較による判断変化
- 完璧主義による停止
- 失敗後の停止
- 過負荷
- 睡眠・疲労由来の低下
- 時間不足
- 現行目標への疑念
- 前提条件変化
- 重大な外部事情
- 目標達成
- 通常状態

など。

ただしこれは例示であり、実際の状態集合は自由意志データをもとにChatGPTが個別生成する。

---

# 24. 状態監査質問バンク

質問候補：

**32〜48問**

推奨：

**約40問**

実際に一度の監査で質問する数ではない。

質問プールとして保持する。

---

# 25. 1回の状態監査質問数

通常：

**6〜10問**

目標平均：

**約8問**

最大：

**12問**

最大数に達したら必ず終了。

ユーザーへ20問、30問と聞き続けない。

---

# 26. 回答形式

5件法。

- はい
- ややそう
- どちらともいえない
- あまり違う
- いいえ

追加：

`判断できない`

も選択可能。

---

# 27. 状態監査アルゴリズム

各状態について事前確率を持つ。

質問ごとに、

`P(answer | state)`

に相当する重みを保持する。

回答ごとに各状態のスコア／確率を更新する。

次質問は、

**期待情報利得が最大になる質問**

を選択する。

概念的にはエントロピー：

```text
H(S) = -Σ P(s) log2 P(s)

```

を使い、

各質問後の期待エントロピーが最も小さくなる質問を選ぶ。

完全な厳密ベイズでなくてもよいが、

単純な固定順質問は禁止。

---

# 28. 停止条件

以下のいずれか。

### 条件A

1位状態の確率：

`>= 0.75`

かつ

2位との差：

`>= 0.20`

### 条件B

質問数12問。

### 条件C

追加質問による情報利得が非常に小さい。

---

# 29. 複合状態

無理に1状態へ決めない。

1位と2位が接近している場合：

```text
主要状態：実行開始困難 51%
副次状態：疲労 34%

```

のように表示可能。

---

# 30. 状態監査結果

表示：

## 判定

状態名。

## 信頼度

高 / 中 / 低

または％。

## 根拠

回答の中で特に寄与した2〜4項目。

## 推奨処理

最大3項目。

原則として具体的だが、日次タスクをAIが生成するわけではない。

例：

「現行目標を変更しない」

「新規計画の作成を停止する」

「現行目標に関連する未完了作業へ復帰する」

## 回避処理

最大3項目。

例：

として実装すること。

# 51. v1.1 実運用調整（2026-09-14）

本節は上記初版仕様と矛盾する場合に優先する。

- 自由意志取得は「手入力」と「ChatGPT Memoryのみ」の2独立経路とする。Memory経路にフォーム入力を混合しない。
- 自由意志記入内容を全消去するリセット機能を追加する。大政奉還データは保持する。
- 心理5件法は選択済みの選択肢を再選択すると未回答へ戻せるようにする。
- 状態監査は最低8問、通常10〜12問を探索する。最大12問は維持する。
- 1回答の過大な影響を抑えるためlikelihoodをtemperingし、同方向の類似質問への偏りを軽く抑制する。
- 結果には主状態と副状態候補、上位候補分布を表示する。
- 行動指示は主状態のみから採用する。副状態は解釈補助であり主状態を上書きしない。
- 決定規則は「基本方針の制約・維持条件 > 主状態の推奨処理 / 回避処理 > 副状態は解釈のみ」とする。
- 状態監査に直前回答の取消を追加する。
