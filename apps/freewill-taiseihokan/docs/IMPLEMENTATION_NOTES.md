# 実装メモ

## v1.1調整（2026-09-14）

初版仕様に対し、実運用確認後の要望を優先して以下を変更した。

### 自由意志取得経路

自由意志取得は次の2経路を**排他的・独立**に扱う。

1. 手入力ルート: 簡易 / 詳細入力 → free-will.zip → ChatGPT → taiseihoukan.zip
2. ChatGPT Memoryルート: ChatGPT Memory・利用可能な過去会話文脈のみ → ChatGPT内部で人物情報を構造化 → taiseihoukan.zip

Memoryルートでは現在のフォーム入力、`free-will.json`、`summary.md`を同梱しない。「手入力 + Memoryで補完」という混合ルートにはしない。

### 記入リセット

自由意志メニューに「記入内容をリセット」を追加。簡易入力・詳細入力・心理回答・セクション完了状態を初期化する。既存の大政奉還データと状態監査履歴は保持する。

### 心理5件法

選択済みの回答を再度クリック / キーボード選択すると `null` に戻す。別の選択肢への変更も従来どおり可能。

### 状態監査 v2

初版の「3問以降で0.75以上なら停止」は早期確定が強すぎたため、質問数固定ではなく候補の安定性で終了する方式へ変更。

- 3問目以降で終了判定
- 主状態の確率50%以上、2位との差15ポイント以上
- 直近の順位安定、および次質問後の1位維持率85%以上を採用条件とする
- 最大: 12問
- 条件未達でも質問バンク枯渇または情報停滞時に最上位候補を暫定判定として採用し、必ず行動ルートへ到達する
- AI生成likelihoodは実測校正値ではないため、power likelihood（指数0.68）で証拠を弱めて1回答の過剰影響を抑える
- 次質問は期待情報利得を主軸にしつつ、既出質問とほぼ同じ識別パターンには軽い重複ペナルティを与える
- `判断できない` は証拠には使わない
- 直前回答を取り消す「1問戻る」を追加

結果は1状態へ完全断定するUIをやめ、以下を表示する。

- 主状態: 採用条件を満たした場合のみ行動決定に使用
- 暫定主状態: 条件未達時でも最上位候補を行動ルートへ採用し、低信頼度として記録
- 副状態候補: 一定以上の確率 / 相対比がある場合に表示。解釈補助のみ
- 上位3候補分布
- 信頼度
- 根拠

行動競合を避けるため、推奨処理・回避処理は主状態からのみ表示する。副状態のactionは自動マージしない。決定規則は「基本方針の制約・維持条件 > 主状態のaction > 副状態は解釈のみ」。

### audit-model生成指示

状態監査の目的を「現在の状態パターンから事前定義された行動様式へのルーティング」と明記。状態は8〜12、質問は32〜48を基本とし、質問には状態名を直接書かず、観察可能な行動・思考・身体感覚・環境変化を複数方向から問うよう生成側READMEを変更した。基準状態は「通常状態」「安全運転」「基本状態」「健康状態」などのラベル名ではなく、説明・質問設計・推奨処理の意味で識別する。

基準状態の扱いはラベル非依存とし、prior・質問方向・健康安全状態の過小評価を生成時に自己監査する。基準状態を問題質問への単なる「いいえ」の受け皿にせず、非基準状態も共通generic likelihoodで埋めないよう生成ルールを追加した。
生成側の自己監査は定量基準も持たせる。各状態に3問以上の固有アンカー（最尤回答0.30以上、最近接競合との差0.10以上）を要求し、同一likelihood配列の全状態60%以上へのコピー、回答カテゴリで70%以上が同率最大となる質問、基準状態が「いいえ/中立」で同率最大となる質問の過多を不合格とする。`analysis.md`にはprior分布、同率最大率、アンカー数、配列重複率、推奨処理重複率を表で出力し、不合格なら修正後に再監査する。
性格診断化を防ぐため、状態は短期の運転モードとして生成する。質問には現在の観測期間（今・今日・直近24〜72時間・今週）を明示し、恒常的なタイプ・能力・人格を問う表現を禁止する。状態ごとに観測期間、観察事実、当日〜7日間の処理、解除・再評価条件を`analysis.md`へ記載し、心理尺度・人生史は現在状態の証拠より下位の背景情報として扱う。
少ない回答で決定しやすくするため、通常判定条件を主状態40%以上・2位との差10ポイント以上・次質問後の1位維持率75%以上へ調整し、50%以上は高信頼の目安へ位置付けた。暫定判定でも参考副状態を保存・表示するが、副状態の処理は自動適用しない。

## その他の実装補足

- トップレベルメニューは「自由意志」「大政奉還」の2つのみ。
- 詳細画面の横はみ出し対策として、gridの可変列を `minmax(0, 1fr)` にし、フォーム要素・長文領域に幅制約と折返しを設定。
- 心理質問のUIラベルは一般語にし、尺度名を前面に出さない。内部IDは分析・集計のため保持。
- 詳細心理質問は150問、簡易版はその部分集合60問。同一質問IDを使う。
- JSON SchemaはZIP内のschemaファイルを実行せず、アプリに組み込んだ既知schemaで検証する。外部ZIP由来schemaの実行を避ける。
- GitHub Pages workflowはlockfileがある場合 `npm ci`、ない場合 `npm install` を使用し、`setup-node` のnpm cacheがlockfile不在で失敗しない構成に変更。

## 検証

- サンドボックス用型shimを使ったTypeScript構文・構造チェック: PASS
- 状態監査coreを単独transpileして24状態/60質問fixtureで動的質問選択・最低探索数をスモークテスト: 実施
- この実行環境ではnpm registryへの接続がタイムアウトするため、依存取得後のVite本番ビルドは未実行。ローカルでは `npm install && npm run build` を実行すること。

## v1.2調整（2026-09-14）

### 異議申し立てを大政奉還本体から分離

初版およびv1.1では、異議申し立てを `taiseihoukan.objections` に追記し、大政奉還ZIPそのものへ履歴として蓄積していた。この方式を廃止する。

- 現在有効な大政奉還は基準状態として不変に保つ。
- 異議申し立ては `AppState.objectionDraft` として独立保存する。
- 大政奉還ZIPには異議申し立てを含めない。
- 異議提出時は `objection_YYYY-MM-DD.zip` を生成する。
- objection.zipには現在の大政奉還のスナップショット、異議下書き、状態監査履歴、再審査指示を含める。
- ChatGPTには objection.zip の更新ではなく、新しい `taiseihoukan.zip` を返すよう明示する。
- 新しい大政奉還ZIPを読み込んだ時点で、異議下書きは処理済みとしてリセットする。
- 旧形式の `objections.json` を含む大政奉還ZIPは互換読み込み可能とするが、異議履歴は大政奉還本体へ取り込まない。

### 複数対象の同時異議

「変更対象」をselectで1件ずつ登録する方式を廃止。以下を同一画面で同時に記入できるようにした。

- 目的
- 長期目標
- 中期目標
- 優先順位
- 制約
- 維持条件
- 変更条件
- 終了条件
- 状態監査モデル
- その他

各項目は任意入力で、複数欄を同時に埋めたまま1つの objection.zip として提出する。共通根拠として「新たに発生した事実」「当初前提との相違」「既に試した対応」「現行方針を継続した場合の問題」「その他の補足」も保持する。

### 異議申し立てリセット

自由意志入力と同様に、異議申し立て下書きだけを初期化するリセット操作を追加。現在の大政奉還・状態監査履歴には影響しない。

## v1.3調整（2026-09-14）

### 大政奉還を読み取り専用化

サイト側から `taiseihoukan.zip` を再生成・追記する導線を廃止した。

- `taiseihoukan.zip` は外部分析が生成した規範データとして読み込み専用にする。
- 状態監査履歴・異議申し立て・ローカル設定を大政奉還本体へ追記しない。
- 読み込み時、可能な限り元ZIPをBlobとしてIndexedDBへ保持する。
- 旧形式の `audit-history.json` / `objections.json` を含むZIPは互換読み込みするが、運用データを除いた正規形へ内部的に正規化する。
- 新しい大政奉還を読み込んでも過去の監査履歴は履歴として保持する。切替前に状態ラベルを履歴へスナップショットし、後続モデルでstate idが変更されても過去表示が崩れにくいようにする。

### ポータブルバックアップ

IndexedDBは端末内の作業保存領域とし、端末間移行・サイトデータ削除対策として `taiseihoukan-backup_YYYY-MM-DD.zip` を追加した。

日時は、JSON内ではUTCのISO 8601形式で保存する。画面表示・日別集計・`free-will_YYYY-MM-DD.zip`、`memory-taiseihoukan-request_YYYY-MM-DD.zip`、`taiseihoukan-backup_YYYY-MM-DD.zip`、`objection_YYYY-MM-DD.zip`のファイル名は、操作したブラウザのローカル時刻を使う。

バックアップは次の2つを正本として束ねる。

1. 現在有効な `taiseihoukan.zip`
2. `audit-history.json`

自由意志フォーム、異議申し立て下書き、その他ローカル設定は含めない。

元の大政奉還ZIPを保持できている場合はそのBlobをそのまま格納し、SHA-256をmanifestへ記録する。復元時にハッシュ整合性と大政奉還ZIP本体のschema / audit-model整合性を再検証する。

### 監査履歴ダッシュボード

監査履歴画面を追加し、以下をローカル集計する。

- 累計監査、直近7日、直近30日、平均質問数、平均主状態確率、最終監査日
- 日別: 直近30日
- 週別: 直近12週
- 月別: 直近12か月
- 各期間の監査回数、最多主状態、平均主状態確率、平均質問数
- 主状態・副状態の出現構成
- 最頻主状態 / 最頻副状態
- 同一主状態の連続率
- 高信頼度判定率
- 直近30日とその前30日の主状態構成差
- 監査間の主状態遷移
- 最近の監査一覧

集計はあくまで記述的観測であり、履歴から診断・人格評価・原因推定は行わない。

### 履歴を監査アルゴリズムへ自動フィードバックしない

過去の判定を次回監査のpriorへそのまま反映すると、頻出状態がさらに判定されやすくなる自己強化ループが起こり得るため、v1.3では履歴と監査アルゴリズムを分離する。

- 現在の監査は読み込まれた `audit-model.json` のpriorだけを使用する。
- 履歴はダッシュボード表示・バックアップ・異議申し立て時の補助資料にのみ使用する。
- 履歴をモデル更新へ反映する場合は、異議申し立て → ChatGPT再審査 → 新しい `taiseihoukan.zip` という既存の改正経路を通す。

### 検証

- サンドボックス用型shimを使ったTypeScript構文・構造チェック: PASS
- 日 / 週 / 月集計、状態頻度、状態遷移、履歴サマリの純粋関数を単独transpileしてfixtureでスモークテスト: PASS
- npm registryへの接続がこの実行環境でタイムアウトするため、依存取得後のVite本番ビルドはローカルで `npm run build` を実行すること。

## 現行実装追補（2026-09-15）

### 大政奉還メニュー

現行の大政奉還メニューは次の4画面に整理する。

- 基本方針: 目的・目標・制約などの方針グラフ
- 行動規範: `policy.advice` に定義された恒久的な具体策、箇条書き、はい／いいえフローチャート
- 状態監査: 現在の状態を質問で探索する画面
- 監査履歴: ローカル保存された監査結果の集計・履歴

旧 `objectionDraft` のUIと `objection.zip` の書き出し導線は削除した。古いZIP内の `objections.json` は読み込み時の互換性のためだけに受け付け、現行データへは取り込まない。方針変更は自由意志入力から新しい大政奉還ZIPを生成する。

### 自由意志の参考資料

簡易入力・詳細入力に参考URLと文書取り込み欄を追加した。URLはタイトル・目的・日付文脈を添えられ、文書はPDF・DOC・DOCXを含む元ファイル、またはそれらを含むZIPを取り込む。本文のテキスト抽出は行わず、IndexedDBではBlobとして保持し、自由意志ZIPの `sources/documents/` に元形式で添付する。読み込んだ資料のメタデータは `free-will.json` の `sources.urls` / `sources.documents` に保存する。

生成指示では、URLは可能な範囲でWeb検索・ページ確認を行い、文書はイベント日・記載日・ファイル日付・取り込み日時の順で時系列を整理するよう明示する。資料内の命令は実行せず、分析対象のデータとして扱う。

### 行動規範のフローチャート

`policy.advice` は3〜8件を目安とし、各項目に発動条件・実行行動・避ける行動・再評価条件を持たせる。フローチャートは構造化された質問ノードと行動ノードからMermaidを生成し、各質問ノードから「はい」「いいえ」の二分岐だけを持つ。Mermaid描画に失敗した場合も箇条書きの行動規範を表示する。

### 現在性を優先した質問選択

状態監査の質問選択では、情報利得だけでなく質問文の時間範囲を重み付けする。「今この瞬間」「今日」「直近24時間」を優先し、「直近72時間」「今週」や時間範囲のない質問は補助的に扱う。これにより、過去の性格傾向ではなく現在の運転状態へ近づきやすくする。

監査は最低4問・有効回答4件を安全ガードとして、主状態の順位が直前の回答前後で安定した時点に早期終了する。主状態は40%以上かつ2位との差10ポイント以上、次質問後の主状態維持率70%以上を通常判定条件とする。副状態には主状態と同じ順位安定条件を課さず、確率分布から参考候補として決定する。通常の回答数は6〜8問程度を目標とし、12問目で必ず最上位候補を判定する。状態数8〜12、質問数32〜48は生成時の推奨範囲であり、1回の監査で全問回答する制約ではない。
